## 1. Summary

Dahan MVP goes live for the first organization: groups, members, activities and attendance, statistics, member views, surveys, and the public `/daftar` interest form. This is a fresh install, so there is no data to migrate and no users to notify. Later, the app is expected to move to its own domain (e.g. `dahan.id`); see section 9.

## 2. Changes

First release; everything on branch `attendance-table` merged to `main` at the tagged commit. Feature scope is defined by `openspec/changes/ngaji-mvp/`.

## 3. Risk and impact

- **Migrations:** all of `prisma/migrations/` applied to an empty database via `migrate deploy`.
- **Config / env:** new `.env` with production values (section 5). Nginx and systemd units installed from `deploy/`.
- **Data impact:** none (empty database). The database will hold member PII from day one.
- **Sessions:** not applicable.
- **Dependency audit exceptions:** the two rows already recorded in DEPLOYMENT.md §5 (`mysql2`, `fast-uri`). Re-check them at deploy time.
- **Shared parent domain:** the app lives on a subdomain of `ilyasmustafa.com`. Keep cookies host-only (the app does, and Auth.js sets no `domain`), and do not add a `Domain=ilyasmustafa.com` cookie anywhere. HSTS (`includeSubDomains`) is sent by `dahan.ilyasmustafa.com` and so pins only that host and its subdomains, not the parent domain or sibling sites.

## 5. Deploy steps (fresh server)

Follow DEPLOYMENT.md in order. Values for this deployment:

| Item | Value |
|---|---|
| Domain | `dahan.ilyasmustafa.com` |
| VPS | IDCloudHost Cloud VPS, Ubuntu 24.04 LTS, 2 vCPU / 2 GB / 40 GB NVMe, Jakarta |
| DNS | `A` record `dahan` → VPS IPv4, in the DNS zone of `ilyasmustafa.com` |
| Nginx site | `deploy/nginx/ngaji.conf` with `ngaji.example.com` replaced by `dahan.ilyasmustafa.com` |
| `DATABASE_URL` | `file:/var/lib/ngaji/production.db` |
| `AUTH_TRUST_HOST` | `true` (behind Nginx) |
| Object Storage | one IDCloudHost bucket for backups, plus a key limited to it |

Order:

1. **VPS:** DEPLOYMENT.md §2 (order the VPS, add SSH key, console firewall 22/80/443 if the plan has one).
2. **DNS:** create the `A` record now and wait until it resolves: `dig +short dahan.ilyasmustafa.com` returns the VPS IP. Certbot in step 6 fails otherwise.
3. **Hardening:** §3 (ufw, fail2ban, swap, SSH key-only, `ngaji` user). Confirm key login from a second terminal before closing the first.
4. **Install:** §4 (Node 24, clone, `pnpm install --frozen-lockfile`, `.env` mode 600 with a **new** `AUTH_SECRET`, `prisma generate`, `prisma migrate deploy`).
5. **Organization:** `pnpm org:create` (§4). **Never run `prisma db seed`.** Choose a strong OWNER password; it is forced to change on first login.
6. **Build and start:** `pnpm build`, install `ngaji.service`, enable it.
7. **Audit gate:** §5.
8. **Nginx and TLS:** §6, using the domain above.
9. **Backups:** §7 in full (bucket, rclone, `backup.env`, healthchecks.io, timer, first manual run).
10. **Restore drill:** §8 on a scratch hourly VPS, **before** entering real data. Log it in the drill table in DEPLOYMENT.md.
11. Sections 6 and 7 below.

## 6. Sanity checks (after deploy)

- [ ] `systemctl status ngaji` is active; `journalctl -u ngaji -n 50` shows no errors and no PII

## 9. Follow-up: moving to its own domain

When `dahan.id` (or another domain) is bought:

1. Add an `A` record for the new host, get a certificate (`certbot certonly --nginx -d <new>`), and add a `server_name` for it in Nginx.
2. Make the new host primary and redirect `dahan.ilyasmustafa.com` to it with a 301.
3. Users must log in again once (cookies are host-only). Record it in that release's section 3.
4. Add a new release document for the change, from [TEMPLATE.md](TEMPLATE.md).
